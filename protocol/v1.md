# Rotary Pendulum serial protocol v1

This protocol is shared by the Python LowLevelClient and Arduino LowLevelServer. It is binary, bounded, request/response, and delimiter framed. `ARM` is an explicit operator command; `HELLO` never arms the driver.

## Wire framing

Each decoded frame has this layout (little-endian integers):

| Field | Size | Value |
|---|---:|---|
| version | 1 | `1` |
| type | 1 | Type table below |
| sequence | 2 | Unsigned 16-bit transaction sequence |
| payload length | 1 | `0..24` |
| payload | 0–24 | Type-specific |
| CRC | 2 | CRC-16/CCITT-FALSE over version through final payload byte |

CRC parameters: polynomial `0x1021`, initial value `0xFFFF`, no reflection, xor-out `0x0000`. The decoded frame is COBS encoded and terminated by `0x00`. Empty COBS packets are ignored. Maximum decoded length is 31 bytes; maximum encoded payload is 32 bytes plus delimiter. AVR implementation uses fixed arrays only, no heap allocation.

The receiver accumulates bytes until delimiter. A partial frame expires after 25 ms; overflow, malformed COBS, invalid length, wrong version, CRC failure, or timeout discards the partial frame and resumes at the next delimiter. Parsing is nonblocking: never wait for the remainder of a frame inside command handling. Parser errors increment diagnostics and produce an error ACK only if a complete, decodable header and sequence are available; otherwise drop the frame.

## Frame types

| Type | ID | Direction | Payload |
|---|---:|---|---|
| HELLO | `0x01` | Host → board | none |
| GET_STATE | `0x02` | Host → board | none |
| SET_ACCEL | `0x03` | Host → board | IEEE-754 binary32 little-endian rad/s² |
| ARM | `0x04` | Host → board | none; explicit operator action only |
| DISARM | `0x05` | Host → board | none; idempotent |
| TARE | `0x06` | Host → board | none |
| ZERO | `0x08` | Host → board | none |
| ACK | `0x80` | Board → host | request type:u8, status:u8, fault_flags:u16 LE |
| HELLO_ACK | `0x81` | Board → host | protocol version:u8, max payload:u8, health_flags:u16 LE, fault_flags:u16 LE |
| STATE | `0x82` | Board → host | `time_us:u32`, motor_pos:f32, pendulum_pos:f32, motor_vel:f32, pendulum_vel:f32, health_flags:u16, fault_flags:u16 (24 bytes) |

All floats are IEEE-754 binary32 little-endian. A receiver rejects NaN and infinity. `SET_ACCEL` is accepted only within the firmware’s configured acceleration bound. A STATE packet is always associated with the GET_STATE sequence that caused it.

Status values: `OK=0`, `BAD_VERSION=1`, `BAD_LENGTH=2`, `BAD_CRC=3`, `BAD_SEQUENCE=4`, `NOT_DISARMED=5`, `INVALID_VALUE=6`, `FAULT_LATCHED=7`, `NOT_ARMED=8`, `UNKNOWN_COMMAND=9`, `STATE_UNAVAILABLE=10`.

Health flags: `ENCODER_VALID=0x0001`, `SAMPLER_FRESH=0x0002`, `STEPPER_READY=0x0004`, `ARMED=0x0008` (informational), `MAGNET_DETECTED=0x0010`. ARM requires `0x0017` (encoder, fresh sampler, stepper ready and magnet detected).

Fault flags are latched until reset: `LEASE_EXPIRED=0x0001`, `ENCODER_STALE=0x0002`, `ENCODER_FROZEN=0x0004`, `ENCODER_INVALID=0x0008`, `HARD_LIMIT=0x0010`, `INTERNAL=0x0020`.

## Sequence and retry rules

The host increments a u16 sequence for every request. The board accepts a sequence only if it is forward of the previous accepted sequence under modular arithmetic: `delta = (new - previous) mod 65536`, with `1 <= delta <= 32767`. Duplicate and old requests are rejected and must never re-execute a command or refresh the lease. HELLO can establish/reset a session only while disarmed; HELLO_ACK echoes its request sequence. Every response echoes the request sequence. A mismatched response is not used to satisfy a different transaction.

GET_STATE and DISARM are idempotent and may be retried with a new sequence after timeout. HELLO may be retried while disarmed. ARM and SET_ACCEL are never automatically retried/replayed. TARE and ZERO are not automatically retried. The host serializes request/response transactions so a response cannot be consumed by another caller; ACKs are drained and sequence-checked before another synchronous transaction completes.

## Command lease and safe response

Only a valid, in-range, sequence-accepted SET_ACCEL refreshes the 100 ms command lease. GET_STATE, HELLO, and ACK traffic do not refresh it. Lease expiry latches a fault and invokes the firmware fail-safe stop/disable behavior; it does not automatically re-arm. DISARM is accepted regardless of sequence freshness when it is a valid complete frame, as an additional fail-safe path, but duplicates do not repeat side effects. The independent hardware E-stop remains outside this protocol and must cut driver enable/power independently.

## Python API

`LowLevelClient.get_state() -> State` remains the state API. `State` retains the original position/velocity/time fields and adds `health_flags`, `fault_flags`, `rx_monotonic_ns`, and `rtt_ns`. `set_acceleration(float)` sends one SET_ACCEL and waits for its matching ACK within the configured transaction deadline; it never retries. ARM/DISARM/TARE/ZERO return an ACK result (including `rtt_ns`) or raise a typed protocol/timeout exception. State decoding rejects non-finite values, mismatched sequence/type, CRC failure, and non-advancing or backward sample timestamps. Host receive age and request RTT are measured on the host monotonic clock.

## Firmware integration hooks

The serial parser/dispatcher calls these safety-owned hooks; the firmware safety implementation owns their bodies:

```cpp
bool safety_is_disarmed();
bool safety_is_armed();
uint16_t safety_health_flags();
uint16_t safety_fault_flags();
uint8_t safety_arm();                 // return protocol status
void safety_disarm(uint8_t reason);   // idempotent; force-stop and disable
uint8_t safety_set_acceleration(float accel_rad_s2);
uint8_t safety_tare();
uint8_t safety_zero();
void safety_note_valid_accel(uint32_t now_ms); // starts/refreshes 100 ms lease
void safety_check_command_lease(uint32_t now_ms); // called continuously from loop()
bool safety_get_state(uint32_t* time_us, float* motor_pos, float* pend_pos,
                      float* motor_vel, float* pend_vel,
                      uint16_t* health_flags, uint16_t* fault_flags);
```

The parser must call `safety_note_valid_accel` only after full frame validation, sequence acceptance, finite/range validation, and successful command acceptance. `safety_check_command_lease` runs every main-loop pass. Protocol parsing itself must not delay sensor sampling or stepper ISR work.
